## 1. 立项概述

### 1.1 背景

检索增强生成（RAG）与向量检索是当前工程界最活跃的方向之一。主流生产级向量数据库（Milvus、Qdrant、Pinecone 等）的核心，都是近似最近邻（ANN）索引，其中 **HNSW（Hierarchical Navigable Small World，分层可导航小世界图）** 是事实上的主流索引：它把向量组织成多层近邻图，上层节点稀疏、负责长距离跳跃，下层节点稠密、负责精确搜索。

与"用框架搭一个 RAG Demo"不同，本项目的核心技术选择是：**在 Java 中从零实现检索内核（含 HNSW 索引），并以电商商品知识库为业务场景，配套自研网络协议网关、页面与完整评测体系**。

### 1.2 项目目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 课程报告拿满分 | 老师四个环节（需求分析、方案论证、系统验证、汇报）均有对应产物与真实数据 |
| G2 | 进入夏令营简历 | 公开仓库可访问；核心模块自研；所有指标可被面试官追问三层 |

### 1.3 技术红线（自我约束）

1. 核心业务、算法、网络层、压测脚本全部使用 Java（JDK 21），不引入 Python 运行时；
2. 第三方仅以 Maven 依赖形式引入，并在报告中如实列明；
3. 所有结论必须对应一次真实运行，保留日志与原始数据；
4. 不做整包 fork 改包名式"二次开发"。

## 3. 需求分析

### 3.1 功能需求（FR）

| 编号 | 功能需求 | 要点 |
|---|---|---|
| FR-01 | 知识库管理 | 商品文档录入、批量导入（CSV/JSON）、编辑、删除；元数据落 H2 嵌入式数据库 |
| FR-02 | 文本向量化 | 主方案：DJL + ONNX Runtime 加载 sentence embedding 模型（Java 原生推理）；保底方案：纯 Java TF-IDF 稀疏向量 |
| FR-03 | 三类索引可切换 | 暴力索引（Brute-Force，精确基线）、IVF 倒排聚类索引、HNSW 分层近邻图索引 |
| FR-04 | 多路检索 | 向量近邻检索、BM25 关键词检索、混合打分（加权融合）与重排 |
| FR-05 | 智能导购 | 基于检索结果组织回答，SSE 流式输出，附引用商品与推荐理由 |
| FR-06 | 自研长连接网关 | Netty 承载，自定义二进制协议，含握手、心跳、断线重连、背压与限流 |
| FR-07 | 监控与评测看板 | 索引规模、QPS、延迟分布、三类索引召回/延迟对比、连接数 |
| FR-08 | 自研压测客户端 | 基于 Netty 的并发压测工具，输出 CSV 原始结果，供报告画图 |

### 3.2 性能需求（NFR，均为验收目标值）

| 编号 | 指标 | 目标值 | 验证方式 |
|---|---|---|---|
| NFR-01 | 数据规模 | 首期 10 万条商品文档，向量维度 384（可配置 768） | 数据集导入计数 |
| NFR-02 | 检索延迟 | 10 万向量下 HNSW Top-10 的 P99 ≤ 20 ms | 压测客户端，样本 ≥ 10 万次请求 |
| NFR-03 | 检索吞吐 | 单节点 HNSW QPS ≥ 1000 | 固定并发阶梯压测 |
| NFR-04 | 长连接规模 | 单网关维持 ≥ 5000 条空闲长连接不泄漏 | 连接压测 + 内存/句柄监控 |
| NFR-05 | 索引构建 | 10 万向量 HNSW 构建耗时 ≤ 10 min | 构建任务计时，保留构建日志 |
| NFR-06 | 增量写入 | 单文档从入库到可被检索 ≤ 500 ms | 写入后立即检索的集成用例 |
| NFR-07 | 召回质量 | HNSW 对暴力检索的 Recall@10 ≥ 0.95 | 评测集批量比对 |
| NFR-08 | 流式响应 | 导购首字节延迟 ≤ 1 s，支持客户端中断 | SSE 集成用例 |

### 3.3 安全需求（SR）

| 编号 | 需求 |
|---|---|
| SR-01 | 管理端 Token 鉴权，写入类接口拒绝匿名访问 |
| SR-02 | 网关按连接限流（令牌桶），超限返回明确错误码而非静默丢弃 |
| SR-03 | 全部输入做长度与格式校验，防 OOM 与协议注入 |
| SR-04 | 审计日志：记录写入、删除、鉴权失败，日志脱敏 |
| SR-05 | 优雅停机：在途请求处理完毕后再释放连接 |

### 3.4 环境与约束

- 开发机：Windows，JDK 21（已确认 OpenJDK 21），Git 2.46.2（已确认）；
- 构建：Maven。当前机器**未安装 Maven**，采用 Maven Wrapper（mvnw），首次运行自动下载，保证工程资料在任何机器上可直接构建；
- 当前机器**未安装 Docker**：部署以单机 JVM 为主；多节点对比降级为"同机多 JVM 进程 + 脚本编排"，不引入 Docker 依赖；
- 存储：H2 嵌入式文件库（元数据）+ 本地索引文件，零外部中间件，保证评阅老师解压即可运行。

## 4. 意图表达与需求分解（SDD 核心）

把"能导购"这一模糊意图，拆成可判定、可验收的用户故事（US）。每条均含 Given/When/Then 验收条件。

### US-01 文档入库与可检索

- Given：一条合法商品文档（id、标题、描述、类目）
- When：调用入库接口
- Then：生成向量并写入指定索引；元数据落库；500 ms 内以该文档自身向量检索可命中（对应 NFR-06）

### US-02 Top-K 检索

- Given：查询文本与索引选择（暴力/IVF/HNSW）、参数（HNSW：efSearch）
- When：发起检索
- Then：返回 Top-K，每条含 id、相似度分数、命中来源（向量/BM25/混合）；结果按分数降序，无重复 id

### US-03 召回质量可验收

- Given：标注评测集（query 与相关文档对）
- When：以暴力检索结果为精确基准运行评测
- Then：输出 Recall@1/10/100；HNSW 在默认参数下 Recall@10 ≥ 0.95（NFR-07），未达标则调参并重测，保留全部版本记录

### US-04 流式导购

- Given：用户提问
- When：触发导购
- Then：SSE 分片返回，首字节 ≤ 1 s（NFR-08）；回答末尾给出引用商品列表；客户端断开后服务端及时终止后续计算，不产生空转

### US-05 长连接与心跳

- Given：客户端经网关完成握手
- When：连接空闲
- Then：每 30 s 心跳一次；连续 3 次无响应则关闭；客户端可按协议重连并恢复会话；全过程在网关日志留痕

### US-06 索引切换与对照

- Given：同一批向量与同一评测集
- When：分别构建暴力、IVF、HNSW 索引
- Then：检索调试台可对同一 query 并排展示三者结果、耗时与命中差异，数据可导出

## 5. 验收规格与评测集

### 5.1 评测维度与指标定义

| 维度 | 指标 | 定义/口径 |
|---|---|---|
| 召回质量 | Recall@K（K=1/10/100） | ANN 结果与暴力 KNN 基准的交集占比 |
| 延迟 | P50 / P95 / P99 | 单次请求端到端耗时，按固定口径采样 |
| 吞吐 | QPS | 阶梯并发下稳定区间的每秒完成请求数 |
| 资源 | 堆内存、GC 次数、索引文件体积 | JVM 日志与文件系统实测 |
| 正确性 | 并发写入一致性、删除可见性 | 快照读用例：写入/删除期间检索不返回脏数据 |

### 5.2 基线对照（实验记录表，实测后填写）

| 索引方案 | Recall@10 | P99 延迟 | QPS | 构建耗时 | 内存/体积 |
|---|---|---|---|---|---|
| 暴力 Brute-Force | 1.000（定义） | 待测 | 待测 | 待测 | 待测 |
| IVF | 待测 | 待测 | 待测 | 待测 | 待测 |
| HNSW（M=16，efConstruction=200，efSearch=50） | 待测 | 待测 | 待测 | 待测 | 待测 |

HNSW 默认参数（可在实验中调整并记录）：M=16（每节点最大连接数）、efConstruction=200（构建期搜索宽度）、efSearch=50（查询期搜索宽度）、mL=1/ln(M)（层级采样参数）。

### 5.3 压测场景表

| 场景 | 内容 | 目标 |
|---|---|---|
| LT-01 | 检索延迟基线：1 并发，10 万次请求 | 取 P50/P95/P99 |
| LT-02 | 吞吐阶梯：并发 10/50/100/200 | 找 QPS 拐点与 P99 恶化点 |
| LT-03 | 长连接：5000 连接空闲 30 min | 无连接泄漏、句柄稳定 |
| LT-04 | 混合负载：70% 检索 + 20% 写入 + 10% 流式 | 验证背压与限流 |
| LT-05 | 故障注入：压测中关闭部分连接 | 验证重连与优雅停机 |

### 5.4 回归用例清单（边界与异常）

1. 空索引检索：返回空集合而非异常；
2. 重复 id 入库：按幂等策略覆盖或拒绝，行为明确；
3. 维度不匹配：拒绝写入并返回校验错误；
4. 超长文本/空文本：截断规则与空值错误明确；
5. 构建中检索：读到旧快照，不允许半构建状态可见；
6. 并发删除与检索交叉：不返回已删除文档；
7. 协议魔数错误/版本不支持：返回对应错误码并断开。

### 5.5 评测集构建

- 语料：公开商品评论/商品语料数据集（如 Amazon Reviews 类），报告中注明名称、版本与引用；
- query-相关文档对：优先使用数据集中天然的查询-商品关系；不足部分用留一法与类目同源规则构造，并在报告中说明构造规则与样本量；
- 评测集与训练/构建语料分离，避免自证。

## 6. 系统架构与模块划分

Maven 多模块工程：

```
shopmind/
├── pom.xml                  # 父 POM，统一依赖版本
├── shopmind-common/         # 协议帧、DTO、距离计算、工具
├── shopmind-index/          # 暴力/IVF/HNSW 索引、BM25、混合打分
├── shopmind-gateway/        # Netty 自研二进制协议、心跳、限流、SSE 推送
├── shopmind-service/        # 知识库、向量化(DJL/TF-IDF)、检索编排、导购
├── shopmind-web/            # Thymeleaf 页面、REST、监控看板
└── shopmind-loadgen/        # 自研 Netty 压测客户端，输出 CSV
```

### 6.1 自研网络协议帧（网关模块规格）

| 字段 | 长度 | 说明 |
|---|---|---|
| magic | 2 B | 固定魔数，用于校验合法帧 |
| version | 1 B | 协议版本 |
| cmd | 1 B | 帧类型：握手/心跳/检索/流式/错误 |
| seq | 4 B | 序列号，用于请求-响应匹配 |
| length | 4 B | body 长度 |
| body | N B | 载荷（JSON 或紧凑二进制） |

### 6.2 声明的第三方依赖（报告中如实列明）

Spring Boot 3.x、Netty、Thymeleaf、H2、DJL（含 ONNX Runtime engine）、JUnit 5、Maven Wrapper。除上述外不引入重型中间件。

## 8. 风险登记

| 风险 | 影响 | 对策 |

| Maven 未安装 | 无法构建 | Maven Wrapper 自动下载；保留离线安装说明 |
