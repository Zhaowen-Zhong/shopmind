# ShopMind 系统验证报告（10 万规模版）

> 数据来源：本机真实运行的原始输出，全部可通过仓库内脚本复现。
> 运行环境：Windows 11 / OpenJDK 21.0（`21+35-2513`）/ 单机 JVM `-Xmx2g` / 压测客户端与服务端同机运行。
> 语料：合成商品语料 **100,000 条**，向量维度 **384**（TF-IDF 哈希投影，可配置），HNSW `M=16, efConstruction=200, 默认 efSearch=100`。
> 结论口径：未测项一律标注"未测"，不以推算值替代实测值；本轮数据不做倒填。

---

## 1. 验证环境与方法

| 项 | 内容 |
|---|---|
| 语料导入 | `java -cp shopmind-loadgen-1.0.0.jar com.shopmind.loadgen.SeedMain 100000 ./data/shopmind` |
| 索引构建 | 应用启动时 `RetrievalService.rebuildFromStore()`，日志记录起止时间 |
| 压测工具 | 自研 Netty 客户端 `LoadGenMain`（自定义协议、请求级 seq 配对、逐请求落 CSV） |
| 延迟口径 | 客户端"发出 SEARCH 帧 → 收到对应 seq 的 SEARCH_RESULT"的端到端耗时 |
| 召回口径 | 与暴力检索 Top-K 结果集求交集占比（Recall@K） |

## 2. 召回质量（NFR-07）

默认参数独立评测（200 条查询，Top-10，以暴力结果为基准）：

| 索引 | Recall@10 |
|---|---|
| HNSW（efSearch=100） | **0.8065** |
| IVF（nprobe=8） | **0.8055** |

HNSW efSearch 前沿扫描（60 条固定查询，Top-10）：

| efSearch | Recall@10 | 平均延迟(μs) |
|---|---|---|
| 100 | 0.7967 | 1,086 |
| 200 | 0.8733 | 1,791 |
| 400 | 0.9133 | 3,198 |
| 800 | 0.9467 | 5,390 |
| 1000 | **0.9500** | 6,433 |

结论：

- 召回随 efSearch 单调上升，**efSearch=1000 时 Recall@10=0.9500，NFR-07 可达成**，对应平均延迟 6.43 ms，仍远低于 20 ms 延迟上限。
- 系统默认保留 efSearch=100 以换取最低延迟（约 1.1 ms），高召回场景由调用方显式传入 efSearch=1000；默认参数下 0.807 的召回如实标注，不包装为达标。
- 为排除并列伪影，对 30 条查询检查暴力结果第 10 名边界的并列情况，并列数为 0。原始数据见 `docs/experiments/100k-recall.csv`。

## 3. 索引构建（NFR-05）

| 项 | 实测 |
|---|---|
| 文档数 | 100,000 |
| 三套索引（暴力 + IVF + HNSW）构建耗时 | **155.3 s**（21:10:58 → 21:13:33） |
| 应用整体启动耗时 | 158.2 s（含建索引；第二次重启实测 163.8 s） |
| 语料批量导入耗时 | 1,155 ms（单连接分批提交，500 条一批） |
| HNSW 图结构 | maxLevel=4，avgDegree=19.4，图内存约 162 MB |
| BM25 词表 | 9,345 个词项 |

结论：**达成**（目标 10 万条 ≤10 min），实测约 2.6 分钟，有余量。

## 4. 检索延迟与吞吐（NFR-02 / NFR-03）

网关限流阈值在上述压测中调至 100,000/秒（避免误伤），三组场景结果：

| 索引 | 并发/速率 | 请求数 | 错误 | 平均(μs) | P50(μs) | P95(μs) | P99(μs) | 实测 RPS |
|---|---|---|---|---|---|---|---|---|
| 暴力（精确基准） | 5 连接 × 20 rps × 20 s | 2,005 | 0 | 30,012.6 | 28,616 | 36,952 | 40,877 | 100.3 |
| IVF（nlist=256，nprobe=8） | 10 连接 × 100 rps × 30 s | 29,990 | 0 | 1,761.7 | 1,747 | 2,721 | 3,223 | 999.7 |
| HNSW（efSearch=100） | 10 连接 × 100 rps × 30 s | 30,000 | 0 | 1,881.8 | 1,815 | 2,830 | 3,446 | 1,000.0 |

结论：

- **NFR-03（QPS ≥1000）达成**：HNSW 实测 1000.0 rps、IVF 999.7 rps，均零错误。
- **NFR-02（P99 ≤20 ms）达成**：HNSW P99 实测 3.45 ms。2 万规模阶段出现的 450 ms 长尾在本轮干净轮次中未再出现，印证长尾来自同机运行环境而非算法缺陷。
- 暴力索引 P99 约 40.9 ms、吞吐仅 100 rps，量化了 ANN 索引约 30 倍的延迟优势。

## 5. 未达成项的归因与改进方向

1. **NFR-06 增量写入未达成**（详见第 9 节）：瓶颈在 H2 自动提交与三套索引在线建图，向量化不是瓶颈。
2. **NFR-07 为参数化达成**：默认 efSearch=100 偏向低延迟，0.95 召回需显式设置 efSearch=1000；后续评估将高召回参数固化为独立运行档位。
3. 早期 450 ms 长尾的环境假设（同机争抢 CPU）在本轮干净轮次中得到支持，但 GC 日志（`-Xlog:gc*`）仍未采集，分离压测机与补全 GC 日志保留为后续验证项。

## 6. 限流生效验证（LT-04 侧证）

默认限流为"每连接 50 容量 / 50 次每秒"，在 10 连接 × 100 rps 施压时：

| 项 | 实测 |
|---|---|
| 发出请求 | 15,310 |
| 被 `RATE_LIMITED` 拒绝 | 14,693 |
| 采集到的有效应答 | 617 |

结论：令牌桶限流按预期生效，且以明确的 ERROR 帧回传（客户端可计数），不是静默丢包。该项为 2 万阶段的"机制正确性"验证，限流逻辑与语料规模无关，本轮不重复施压。**该项不构成性能结论**。

## 8. 长连接稳态验收（NFR-04）

方法：`ConnLoadMain` 一次性建立 5000 条 TCP 长连接并完成握手，每 30 秒批量心跳，每 60 秒采样一次，持续 30 分钟。

| 观测项 | 实测 |
|---|---|
| 30 分钟内活跃连接数 | 始终为 **5000**，零被动断开 |
| 客户端堆已用 | 21–229 MB 锯齿波动，GC 后回落，**无单调上涨（无泄漏）** |
| 客户端线程数 | 始终 12，无线程泄漏 |
| 客户端主动关闭后服务端 activeConnections | 归零（5000 → 0），服务端工作集约 529 MB 稳定 |

结论：**NFR-04 达成**。该用例验证连接管理，与语料规模无关，沿用 2 万阶段实测。原始数据见 `docs/experiments/LT-03-connload.csv`。

## 9. 增量写入验收（NFR-06）

方法：复制 10 万数据目录为独立副本（避免污染主知识库），`IncrementalMain` 在副本上连续写入 30 条文档，每条写入后立即检索其唯一短语确认"可检索"，口径覆盖 H2 写入 → 向量化 → 三套索引同步写入 → BM25。

| 指标 | 实测（μs） |
|---|---|
| 平均 | 3,159 |
| P50 | 3,048 |
| P95 | 4,382 |
| P99 | 4,641 |

结论：**NFR-06 未达成（目标 ≤500 μs）**。阶段探针（预热均值）：H2 单条自动提交 1,092 μs、向量化 62 μs、含重复写库的全链路 5,280 μs。改进方向：写入先落内存 delta 索引并周期合并（热写不触发在线建图）、H2 异步日志、WAL 队列解耦写入与检索。

## 10. 流式导购首字节验收（NFR-08）

方法：对 `/api/guide` 连续 5 轮测量首字节到达时间，并校验完整流正常结束。

| 轮次 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 首字节 (ms) | 203.7 | 38.1 | 9.8 | 9.0 | 9.7 |

结论：**首字节目标（≤1 s）达成**，平均 54.1 ms，预热后稳定在 9–38 ms。客户端中断方面：模板响应约 250–480 ms 即自然结束，无法稳定复现"长流中途取消"，已在 API 层验证取消令牌可释放连接；接入大模型后的长流中断需按同口径补测。原始数据见 `docs/experiments/100k-sse-summary.json`。

## 11. 故障注入与优雅停机验收（LT-05）

`GracefulShutdownTest` 两条用例（真实起停 Netty 服务）：

| 用例 | 结果 |
|---|---|
| 优雅停机：已建连接逐个关闭、事件循环终止、原端口拒绝新连接 | 通过 |
| 服务重启：客户端退避重试（最多 10 次 × 200 ms）后重新握手成功 | 通过 |

## 13. 本轮验证的可复现命令

```bash
# 1) 生成语料
java -cp shopmind-loadgen/target/shopmind-loadgen-1.0.0.jar com.shopmind.loadgen.SeedMain 100000 ./data/shopmind

# 2) 启动服务（放开限流以便测吞吐；限流验证时用默认 50）
java -Xmx2g -jar shopmind-web/target/shopmind-web-1.0.0.jar \
     --shopmind.gateway.limit-capacity=100000 --shopmind.gateway.limit-refill=100000

# 3) 压测
java -cp shopmind-loadgen/target/shopmind-loadgen-1.0.0.jar com.shopmind.loadgen.LoadGenMain \
     connections=10 rate=100 duration=30 kind=hnsw alpha=1.0 out=docs/experiments/100k-lt02-hnsw.csv

# 4) 召回评测
python .tools/report/recall_100k.py

# 5) 增量写入（应用停止后，对数据副本运行）/ 首字节
java -cp shopmind-loadgen/target/shopmind-loadgen-1.0.0.jar com.shopmind.loadgen.IncrementalMain ./data/shopmind
python .tools/report/ttfb_100k.py
```

逐请求汇总 CSV 已入库；更大规模的 raw 文件按 `.gitignore` 约定以 `-raw` 命名后不入库。
